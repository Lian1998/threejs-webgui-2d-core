## 二、在 WSL2 中安装 uv / uvx

以下命令均在 **WSL2 Ubuntu 终端**执行。

### 1\. 安装基础依赖

```bash
sudo apt update
sudo apt install -y curl ca-certificates netcat-openbsd
```

### 2\. 安装 uv

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

加载环境变量：

```bash
source "$HOME/.local/bin/env"
```

验证安装：

```bash
uv --version
uvx --version
which uvx
```

通常安装路径为：

```text
/home/<username>/.local/bin/uvx
```

### 3\. 安装 Python 运行环境

建议使用 Python 3.12，由 uv 独立管理，不影响 Ubuntu 系统自带的 Python。

```bash
uv python install 3.12
```

验证：

```bash
uv python list --only-installed
```

## 三、配置 WSL2 与 Windows 的网络通信

这一步是整个部署的关键。

### 方案 A：镜像网络模式（推荐）

适用于支持 Mirrored Networking 的 Windows 11 22H2 及以上系统和相应版本的 WSL。

在 **Windows PowerShell** 执行：

```powershell
wsl --version
wsl --update
```

打开 WSL 全局配置文件：

```powershell
notepad "$env:USERPROFILE\.wslconfig"
```

添加以下配置，如果已经存在 `[wsl2]` 配置段，则合并进去：

```ini
[wsl2]
networkingMode=mirrored
```

保存后执行：

```powershell
wsl --shutdown
```

注意：该命令会关闭所有正在运行的 WSL 实例。

重新打开 Ubuntu，并确保 Windows Blender 的 MCP 插件仍处于监听状态。

在 WSL2 中测试：

```bash
nc -vz -w 3 127.0.0.1 9876
```

预期输出类似：

```text
Connection to 127.0.0.1 9876 port [tcp/*] succeeded!
```

如果连接成功，可以直接进入第四步。

### 方案 B：保留默认 NAT 网络模式

如果不想修改 WSL2 的网络模式，可以通过 Windows 宿主机 IP 进行通信。

在 WSL2 中执行：

```bash
export BLENDER_HOST=$(ip route show default | awk 'NR==1 {print $3}')

echo "$BLENDER_HOST"
```

可能输出类似：

```text
172.28.224.1
```

测试 Windows 端口：

```bash
nc -vz -w 3 "$BLENDER_HOST" 9876
```

如果连接失败，在 Windows PowerShell 中检查 Blender 实际监听的地址：

```powershell
Get-NetTCPConnection -LocalPort 9876 -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

根据输出判断：

| LocalAddress | 含义 |
|--------|--------|
| `127.0.0.1` | 仅监听本地回环接口 |
| `0.0.0.0` | 监听所有 IPv4 接口 |
| `172.x.x.x` | 监听指定网络接口 |

如果 Blender 只监听 `127.0.0.1`，默认 NAT 模式下通常无法直接通过宿主机 IP 连接。此时优先采用方案 A，而不是直接将 Blender 端口暴露到所有网络接口。

两种方案对比：

| 对比项 | Mirrored | NAT |
|--------|--------|--------|
| Blender Host | `127.0.0.1` | Windows 网关 IP |
| IP 稳定性 | 固定 | 可能变化 |
| 配置复杂度 | 低 | 较高 |
| 本地回环访问 | 支持 | 默认不支持 |
| 推荐程度 | 推荐 | 备选 |

## 四、在 WSL2 中安装 MCP for Blender

按照你架构中指定的 `mcp-for-blender` 包进行安装。

目前该项目支持通过 `BLENDER_HOST` 和 `BLENDER_PORT` 环境变量指定 Blender 的连接地址，也支持通过 `--host` 和 `--port` 参数设置。\[[Install MCP for Blender: Advanced Setup and Configuration](https://www.mcp-for-blender.com/docs/installation?utm_source=chatgpt.com); [GitHub](https://github.com/ahujasid/mcp-for-blender?ref=taaft&utm_source=chatgpt.com)\]

### 1\. 首次运行 MCP Server

假设你采用镜像网络模式：

```bash
BLENDER_HOST=127.0.0.1 \
BLENDER_PORT=9876 \
uvx --python 3.12 mcp-for-blender
```

首次执行时，uvx 会自动完成：

- 创建独立 Python 运行环境。
- 下载 `mcp-for-blender`。
- 安装相关 Python 依赖。
- 启动基于 STDIO 的 MCP Server。

启动后如果终端没有返回 Shell 提示符，而是处于等待状态，这是正常现象。MCP Server 此时正在等待客户端通过 STDIO 发送请求。

完成初步检查后，按 `Ctrl+C` 退出。

**不需要将该进程作为后台服务常驻。** 后续由 Codex CLI 自动启动和管理。

## 五、将 MCP Server 注册到 Codex CLI

有两种配置方式，任选一种即可，无须重复配置。

### 方式 A：使用 Codex CLI 命令

先确认 Codex 安装正常：

```bash
codex --version
codex mcp list
```

注册 MCP Server：

```bash
codex mcp add blender \
  --env BLENDER_HOST=127.0.0.1 \
  --env BLENDER_PORT=9876 \
  -- "$(command -v uvx)" --python 3.12 mcp-for-blender
```

如果采用 NAT 网络模式，则改为：

```bash
codex mcp add blender \
  --env BLENDER_HOST="$(ip route show default | awk 'NR==1 {print $3}')" \
  --env BLENDER_PORT=9876 \
  -- "$(command -v uvx)" --python 3.12 mcp-for-blender
```

查看注册结果：

```bash
codex mcp list
```

查看 Blender MCP 的具体配置：

```bash
codex mcp get blender
```

### 方式 B：手动修改 config.toml（推荐）

Codex CLI 支持通过 `~/.codex/config.toml` 配置 STDIO 类型的 MCP Server。\[[GitHub - ahujasid/mcp-for-blender at piotrkrzyzek.com](https://github.com/ahujasid/mcp-for-blender?ref=piotrkrzyzek.com&utm_source=chatgpt.com)\]

打开配置：

```bash
mkdir -p ~/.codex
nano ~/.codex/config.toml
```

追加以下内容，不要覆盖原有的 Codex 配置。

```toml
[mcp_servers.blender]
command = "/home/YOUR_USERNAME/.local/bin/uvx"
args = ["--python", "3.12", "mcp-for-blender"]
enabled = true
startup_timeout_sec = 120
tool_timeout_sec = 180

[mcp_servers.blender.env]
BLENDER_HOST = "127.0.0.1"
BLENDER_PORT = "9876"
```

将 `YOUR_USERNAME` 替换为你的 Ubuntu 用户名，或者通过下面的命令获取完整路径：

```bash
which uvx
```

配置说明：

| 参数 | 用途 |
|--------|--------|
| `command` | uvx 可执行文件的绝对路径 |
| `args` | Python 版本及 MCP 包 |
| `enabled` | 启用该 MCP Server |
| `startup_timeout_sec` | MCP 启动超时时间 |
| `tool_timeout_sec` | MCP 工具调用超时时间 |
| `BLENDER_HOST` | Windows Blender 的连接地址 |
| `BLENDER_PORT` | Blender TCP 监听端口 |

使用绝对路径，可以避免 Codex 子进程无法正确继承 Shell PATH 的问题。

## 七、常见故障排查

| 错误 | 可能原因 | 解决方法 |
|--------|--------|--------|
| `uvx: command not found` | PATH 未加载 | 使用 uvx 绝对路径 |
| `Connection refused` | 地址错误或插件没有监听 | 检查 `BLENDER_HOST` |
| `Connection timed out` | 防火墙或网络问题 | 使用 `nc` 测试 TCP |
| `MCP startup timeout` | 首次下载依赖耗时 | 手动运行 uvx 预热缓存 |
| `MCP handshake failed` | MCP 进程启动异常 | 手动启动检查日志 |
| MCP 已加载，但调用失败 | Blender TCP 不通或版本不匹配 | 检查网络及插件版本 |
| WSL 重启后连接失败 | NAT 网关 IP 变化 | 使用镜像网络模式 |

另外，`codex mcp list` 显示 `enabled` 只说明注册成功，不代表已经与 Blender 建立 TCP 连接。必须实际调用一次场景读取工具才能确认。

## 九、安全及版本注意事项
